## What This Project Tracks

This project tracks the New York Times bestseller lists across five genre categories — Hardcover Fiction, Hardcover Nonfiction, Young Adult Hardcover, Combined Print & E-Book Fiction, and Combined Print & E-Book Nonfiction — and analyzes which genres have the most turnover over time.

The NYT bestseller lists are a culturally significant weekly snapshot of what America is reading. By collecting them over time, this project reveals which genres churn through new titles quickly (high reader demand for novelty) versus which genres keep the same books on top for weeks (loyal, sticky readership). A single week's list tells you what's popular right now; ten weeks of data tells you something about the nature of each genre's audience.

---

## Data Source

**API:** New York Times Books API (`https://api.nytimes.com/svc/books/v3`)  
**Cadence:** Weekly — the NYT publishes updated bestseller lists every Sunday, so the ingestion pipeline runs on a `rate(7 days)` CloudWatch EventBridge schedule.  
**Backfill:** On first deployment, the ingest Lambda was run in backfill mode to collect the previous 10 weeks of historical data, giving the project a meaningful dataset from day one.

## Architecture

### Part 1 — Ingestion Pipeline

| Component | Description |
|---|---|
| **CloudWatch EventBridge Rule** | Fires every 7 days, triggering the ingest Lambda |
| **Ingest Lambda** (`ingest/lambda_function.py`) | Fetches each bestseller list from the NYT API and writes timestamped records to DynamoDB. Also regenerates the plot PNG and uploads it to S3 after each run. |
| **DynamoDB Table** (`nyt-books`) | Persistent store for all collected data |
| **S3 Bucket** (`dp3-nyt-books`) | Stores the publicly accessible plot image at a fixed key |

### DynamoDB Schema

| Attribute | Type | Description |
|---|---|---|
| `list_name` | String (Partition Key) | NYT list identifier, e.g. `hardcover-fiction` |
| `timestamp` | Number (Sort Key) | Unix epoch of the ingestion run |
| `run_date` | String | Human-readable date, e.g. `2026-04-27` |
| `books` | List | Each item contains `rank`, `title`, `author`, `weeks_on_list`, `publisher` |

This schema allows efficient queries by list name sorted by time — the exact access pattern the API needs for both the `/current` and `/trend` resources.

## Part 2 — Integration API

Built with **Chalice**, deployed to **AWS API Gateway + Lambda**.

### Zone Apex — `GET /`

Returns the project description and list of available resources.

---

### `GET /current`

Returns the #1 ranked book on each tracked list from the most recent week of collected data.

---

### `GET /trend`

Analyzes the last 10 weeks of data and computes which list had the most turnover (most distinct #1 books) and which was the most stable. This is a derived metric that only becomes meaningful after multiple weeks of collection.

---

### `GET /plot`

Returns the URL of a publicly accessible PNG bar chart stored in S3. The chart shows the total number of unique titles that appeared on each list over the last 10 weeks — a measure of genre turnover. The plot is generated by the ingest Lambda using matplotlib after each weekly run and uploaded to S3 at a fixed key, so the URL is always stable and the image always reflects the latest data.

## Implementation Notes

### Logging & Exception Handling

Both the ingest Lambda and the Chalice API use Python's `logging` module throughout. Every fetch, write, and query operation is wrapped in `try/except` blocks with specific exception types (`HTTPError`, `ClientError`, `KeyError`, etc.) logged individually. Failures in one list or one week never crash the overall run — the pipeline logs the error and continues to the next item.

### Idempotency

The ingest Lambda uses DynamoDB `put_item`, which overwrites existing records with the same partition + sort key. This means the Lambda can be safely re-run without creating duplicate records.

### Rate Limiting

The NYT API allows 5 requests per minute on the free tier. The ingest Lambda sleeps 12 seconds between each API call to stay within this limit.

### Plot Generation

The `/plot` resource uses the "render on write" pattern — the ingest Lambda generates the PNG using matplotlib after each weekly run and uploads it to S3. The Chalice API simply returns the stable S3 URL, avoiding heavy dependencies in the API Lambda.

---

## Extra Info

- **Backfill mode:** The ingest Lambda supports a `BACKFILL_MODE` environment variable that, when set to `true`, walks back through the last n Sundays and populates historical data on first deployment.
- **Render on write:** Plot generation was moved to the ingest Lambda to avoid matplotlib's package size limitations in Chalice, following the preferred architecture pattern from the assignment spec.
